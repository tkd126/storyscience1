# 수업용 기사 읽기 사이트 설계

## 목적

광고와 주변 메뉴 때문에 수업 흐름이 끊기는 네 개의 기사를 초등학생이 한곳에서 비교해 읽도록 돕는다. 기사 원문을 복제하지 않고, 정확한 서지 정보와 새로 작성한 학생용 요약, 핵심 쟁점, 수업 질문, 원문 링크를 제공한다.

## 저작권 범위

- 기사 제목, 언론사, 기자명, 작성일처럼 사실에 해당하는 서지 정보는 원문대로 표시한다.
- 본문은 문장이나 문단을 옮기지 않고 사이트용으로 새롭게 요약한다.
- 원문 사진은 복제하거나 내려받지 않는다. 화면의 시각적 구분은 색, 타이포그래피, 간단한 CSS 도형과 아이콘으로 만든다.
- 각 기사에는 언론사와 원문으로 이동하는 분명한 링크를 둔다.
- 사이트 하단에 `이 자료는 수업을 위한 기사 안내·요약 자료이며, 기사와 사진의 저작권은 각 언론사와 저작자에게 있습니다.`라고 표시한다.
- 사용자가 나중에 언론사의 재게시 허가를 확보한 자료를 제공하면 그 범위 안에서만 본문이나 사진을 추가한다.

## 대상 기사

1. 울산저널i, 정승현 기자, 2022-07-11, `“이제 채식 급식으로 지구를 지켜요” 울산 교육 현장의 채식 바람`
2. 서울신문, 김소라 기자, 2021-04-08, `아침 굶는 학생 많은데 학교서 채식한다네요`
3. EBS NEWS, 장아연 스쿨리포터, 2019-09-12, `<스쿨리포트> 수업에 활용하는 스마트폰‥학생, 교사 모두 "만족"`
4. 뉴시스(Daum 뉴스 제공), 이현주 기자, 2026-05-05, `어린이 스마트폰 중독 대책은?…교육장관 "우려 공감"`

기사 날짜는 화면에는 `YYYY년 M월 D일` 형식으로 통일하되 값은 위 원문을 따른다. 서울신문 기사는 입력 시각 기준 날짜를 표시한다.

## 정보 구조와 학생 흐름

한 페이지에서 다음 순서로 이용한다.

1. 첫 화면에서 `학교 급식`과 `스마트폰` 두 주제 및 네 기사 목록을 바로 본다.
2. 기사 카드를 누르면 같은 페이지의 읽기 영역이 해당 기사로 바뀐다.
3. 읽기 영역에서 기사 정보, 한 문장 핵심, 3~5개의 짧은 요약 문단, 핵심 낱말, 생각 질문을 읽는다.
4. 필요한 경우 `원문 기사 보기`를 눌러 새 탭에서 출처를 확인한다.
5. 주제 끝의 `두 기사를 함께 생각하기` 질문으로 서로 다른 관점과 근거를 비교한다.

첫 화면에 긴 소개나 홍보 문구를 두지 않는다. 학생이 페이지를 열자마자 첫 기사와 기사 선택 버튼을 볼 수 있게 한다.

## 기사별 콘텐츠 구성

각 기사 데이터는 다음 필드를 가진다.

- `id`: 화면 전환과 주소 해시에 쓰는 짧은 식별자
- `topic`: 학교 급식 또는 스마트폰
- `publisher`, `author`, `publishedAt`, `title`, `sourceUrl`
- `oneSentence`: 기사의 중심 내용을 표현하는 한 문장
- `summary`: 학생 눈높이로 다시 쓴 짧은 문단 배열
- `keywords`: 어려운 낱말과 한 문장 설명
- `questions`: 사실 확인 1개, 근거 찾기 1개, 자기 생각 1개

기사 요약은 원문의 주장과 반론을 혼동하지 않게 `무슨 일이 있었나`, `왜 필요하다고 보나`, `어떤 걱정이 있나`가 드러나도록 쓴다. 스마트폰 기사도 활용의 장점과 과의존의 위험을 각각 분명히 구분한다.

## 화면 구성과 시각 방향

시각 주제는 `교실에서 펼쳐 보는 두 면짜리 어린이 신문`이다.

- 상단: 사이트 제목 `우리 반 기사 읽기`, 주제 전환 버튼, 글자 크기 조절 버튼
- 왼쪽 또는 모바일 상단: 네 기사 선택 카드
- 본문: 넓은 읽기 칼럼, 기사 정보, 요약, 낱말, 질문
- 하단: 주제 비교 질문과 저작권·출처 안내
- 학교 급식은 짙은 초록, 스마트폰은 짙은 파랑을 강조색으로 사용한다.
- 본문은 18px 이상, 버튼과 카드 라벨은 14px 이상을 유지한다.
- 프로젝터에서도 읽히도록 흰 바탕과 진한 글자, 넉넉한 줄 간격을 사용한다.
- 모바일에서는 기사 목록이 가로 스크롤 가능한 큰 버튼으로 바뀌고 본문이 한 열로 배치된다.

## 동작과 접근성

- 기사 카드는 마우스, 터치, 키보드로 선택할 수 있다.
- 선택된 기사에는 색뿐 아니라 테두리와 `선택됨` 상태가 함께 표시된다.
- `글자 크게` 버튼은 본문 크기를 한 단계 키우고 브라우저 저장소에 선택을 기억한다.
- URL 해시로 선택 기사를 나타내 새로고침하거나 링크를 공유해도 같은 기사가 열린다.
- JavaScript가 꺼져도 네 기사의 제목, 서지 정보, 원문 링크는 기본 HTML에서 확인할 수 있게 한다.
- 외부 링크에는 새 창이 열린다는 것을 보조기기에 알린다.

## 오류 처리

- 주소 해시에 없는 기사 ID가 들어오면 첫 기사를 연다.
- 브라우저 저장소를 사용할 수 없어도 기본 글자 크기로 정상 작동한다.
- 원문 사이트가 일시적으로 열리지 않아도 요약 자료는 그대로 읽을 수 있다.
- 기사 데이터에 필수 필드가 빠지면 자동 검사에서 실패하도록 한다.

## 구현 범위

- 기존 과학 게임 파일은 수정하지 않는다.
- 새 사이트는 저장소 안의 `classroom-news-reader/`에 만든다.
- Sites 기본 프로젝트를 사용하되 데이터베이스, 로그인, 검색, 댓글, 공유 기능은 추가하지 않는다.
- 정적 사이트로 빌드해 학교 컴퓨터에서도 빠르게 열린다.
- 기본 배포는 비공개 주소로 하고, 사용자가 확인한 뒤 공개 범위는 별도로 결정한다.

## 검증

- 자동 검사: 기사 네 개 존재, 제목·언론사·기자명·날짜·원문 URL 일치, 요약과 질문 존재, URL 해시 선택, 잘못된 해시의 기본값, 글자 크기 저장 실패 대응
- 빌드 검사: 정적 배포 파일 생성 여부
- 수동 확인: 데스크톱과 휴대전화 폭에서 첫 기사 표시, 기사 네 개 전환, 주제 색 구분, 글자 크게, 키보드 선택, 네 원문 링크
- 본문·사진 원문 복제 여부를 마지막으로 다시 확인한다.

## 완료 기준

- 첫 화면에서 학생이 설명 없이 네 기사 중 하나를 선택할 수 있다.
- 각 기사에서 출처, 기자, 날짜, 핵심 요약, 낱말, 세 가지 질문을 읽을 수 있다.
- 두 주제에서 서로 다른 기사 관점을 비교할 수 있다.
- 광고가 사이트 안에 나타나지 않는다.
- 기사 원문과 사진을 무단 복제하지 않는다.
- 네 원문 링크가 정확하고 사이트 빌드가 성공한다.
